# TaskFlow

TaskFlow — учебное React-приложение для управления проектами и задачами внутри команды.

Проект собирается как SPA на `React + Vite`, использует `react-router-dom` для маршрутизации и `zustand` для общего состояния.

## Что уже реализовано

### Общая архитектура
- настроен `MainLayout` с общим каркасом приложения
- подключен `react-router-dom`
- реализованы основные маршруты:
  - `/` - `Dashboard`
  - `/projects` -`Projects`
  - `/analytics` - `Analytics`
  - `/settings` - `Settings`
- sidebar и header вынесены в отдельные компоненты

### Интерфейс
- sidebar закреплен слева через `position: fixed`
- header закреплен сверху через `position: fixed`
- основная часть страницы смещается с учетом фиксированных блоков
- реализована светлая и темная тема
- тема сохраняется между перезагрузками через `localStorage`

### Zustand
Сейчас в проекте есть 2 store:

#### `themeStore`
Хранит:
- текущую тему: `light | dark`
- функцию `toggleTheme`

Механика:
- тема читается из `localStorage` при старте
- в `App.jsx` класс `dark` ставится на `html`
- CSS-переменные переключают оформление страниц

#### `projectStore`
Хранит:
- список проектов
- `addProject`
- `updateProjectTasks`

Механика:
- проекты сохраняются через `persist`
- новые проекты из модалки сразу попадают в store
- `Dashboard` и `Projects` читают один и тот же список проектов

### Dashboard
На главной странице реализовано:
- заголовок и приветственный блок
- карточки статистики
- блок `Active Projects`
- блок `High Priority Tasks`
- блок `Upcoming Deadlines`

Особенности:
- список проектов берется из `projectStore`
- progress-bar считается автоматически из `completed / total`
- страница уже реагирует на новые проекты из модалки

### Projects
Страница `Projects` уже не живет на локальном массиве:
- проекты читаются из `projectStore`
- при выборе проекта открывается board-view этого проекта
- можно добавлять задачи внутрь выбранного проекта
- после добавления задач store обновляется, а вместе с ним и `Dashboard`

### Modal New Project
Модалка создания проекта уже рабочая:
- открывается из sidebar
- хранит локальное состояние формы
- позволяет выбрать цвет проекта
- создает новый проект через `projectStore`
- после создания закрывается

### Settings
На странице настроек уже есть:
- блок управления темой
- заглушки под экспорт / импорт / очистку данных
- блок `Storage Info`
- блок `About`

## Как устроена механика проекта

### 1. Layout
`MainLayout` — это общая рамка приложения:
- sidebar
- header
- content area через `Outlet`

Это позволяет не дублировать одинаковую разметку на каждой странице.

### 2. Theme switching
Механика темы работает так:
1. `themeStore` хранит тему
2. `Header` и `Settings` вызывают `toggleTheme`
3. `App.jsx` следит за изменением темы через `useEffect`
4. на `html` вешается или снимается класс `dark`
5. CSS-переменные меняют оформление страниц

### 3. Проекты
Механика проектов работает так:
1. store хранит массив `projects`
2. `ModalProject` вызывает `addProject`
3. `Dashboard` автоматически перерисовывается
4. `Projects` тоже показывает эти же данные

### 4. Задачи внутри проекта
Механика задач пока базовая:
1. пользователь открывает проект
2. добавляет задачу через форму
3. вызывается `updateProjectTasks`
4. store обновляет `taskList`, `total`, `completed`
5. `Dashboard` и `Projects` получают актуальные числа

## Что еще предстоит реализовать

### По данным и логике
- полноценный `taskStore`
- единый источник данных для аналитики
- связать статистику `Dashboard` с реальными задачами, а не с частично моковыми блоками
- экспорт / импорт данных
- очистку данных

### По страницам
- закончить `Analytics`
- довести `Settings` от заглушек до рабочих действий
- при необходимости вернуть отдельную страницу `Board`, если она нужна отдельно от `Projects`

### По UX
- нормальную иконку уведомлений в `Header`
- мобильную стратегию для fixed sidebar/header
- более полную dark-theme поддержку для всех декоративных элементов
- полировку анимаций, hover/focus states и адаптива

## Текущий статус

На текущем этапе проект уже умеет:
- переключать тему
- сохранять тему между перезагрузками
- создавать проекты
- хранить проекты в общем store
- показывать эти проекты на нескольких страницах
- добавлять задачи в выбранный проект

То есть это уже не просто каркас, а рабочая основа приложения.
